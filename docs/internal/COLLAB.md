# NovaCampus 协同规约（Qoder ⇄ Zcode）

> 定义 Qoder（负责人 / 架构 / Review）与 Zcode（实现）在同一仓库协作的规则。
> 目标：杜绝"两个一起改错"。
> 核心手段 = **单一事实来源（TASKS.md）+ 交接棒（同一时刻只有一个写入者）+ 分支隔离 + Review 闸门**。

## 一、角色分工

| 角色 | 承担者 | 职责 | 默认领地（可写） |
|------|--------|------|------------------|
| 负责人 / 架构 / Review | **Qoder（我）** | 拆解计划、下发任务规格、把控架构决策、Review 合并、维护任务板与评测/文档 | `docs/`、`evals/`、`reports/`、`corpus/` 元数据 |
| 实现 | **Zcode** | 按任务规格实现代码、自测、提交、回填交接回执 | `novaagent/`、`mcp/`、`sims/` |

> 领地不是死的，**以每条任务的「允许改的文件」白名单为准**；跨领地改动必须在任务规格里显式授权，否则视为越界，Review 直接打回。

## 二、执行模型：串行交接（一次一棒）

**铁律：同一时刻只有「持棒者」能写工作区，另一方只读。**

- 任务板顶部 `当前持棒` 字段指明持棒者。
- 交接棒只在「我 Review 通过 / 打回」时转移。
- 一次只推进一条任务，不并行开多条。

一条任务的生命周期：

1. **【我】** 在 `TASKS.md` 写好任务规格（目标 / 白名单 / 禁改 / 完成标准 / 验收命令），状态 `READY`。交给 Zcode 时置 `IN_PROGRESS`、`当前持棒 = Zcode`。
2. **【Zcode】** `git checkout -b task/T<id>-<slug>`，实现 + 自测 + commit。
3. **【Zcode】** 回填「交接回执」（分支名 / diff 摘要 / 自测结果 / 完成标准自评 / 遗留问题），状态置 `IN_REVIEW`、`当前持棒 = Qoder`。
4. **【我】** Review：`git diff master..task/T<id>-<slug>` + 跑冒烟 + 逐条核对完成标准。
   - **通过** → `git merge --no-ff` 进 master，状态 `DONE`，删任务分支。
   - **打回** → 回执下写清原因，状态 `REJECTED`、`当前持棒 = Zcode`，Zcode 同分支修。
5. 下一条任务，回到 1。

## 三、分支约定

- `master`：始终可演示、可跑通冒烟。**只有我能合并进来。**
- `task/T<id>-<slug>`：每个任务一条，从 master 切出。串行模型下同一时刻只有一条活跃。
- 提交信息：`T<id>: <做了什么>`（例：`T2: 新增 bad case 提取脚本`）。

## 四、交接契约

### 我 → Zcode（任务规格，写在 TASKS.md 每条任务下）
- **目标**：一句话说清做完什么样
- **允许改的文件/目录**：白名单
- **禁改文件**：黑名单（尤其 `novaagent/` 核心、`evals/run_evals.py`，除非本任务就是改它）
- **完成标准**：可勾选、可验证的清单
- **验收命令**：怎么自测（跑哪个脚本 / 测试）
- **上下文**：相关文件路径、已知坑

### Zcode → 我（交接回执，任务完成后回填到该任务下）
- 分支名 + 提交 hash
- diff 摘要（改了哪些文件、各做了什么）
- 自测结果（跑了什么命令、关键输出行、pass/fail）
- 完成标准逐条自评（✅ / ❌）
- 遗留问题 / 需要我决策的点

## 五、Review 闸门（我合并前必做）

1. `git diff master..task/...` 通读，确认**没越界改禁改文件**。
2. 跑该任务验收命令 + 冒烟与评测（**两者都必须显式 `--base`**，自 `9089fe1` 起`run_evals.py` 缺 `--base` 直接退出码 2；不要再用 `:8900`，那是他人常驻实例，会审到旧代码造出假红 —— 坑 57/61）：
   `bash docs/p4d/run_with_server.sh <端口> tests/smoke_test.py --base http://127.0.0.1:<端口>`、`bash docs/p4d/run_with_server.sh <端口> ../evals/run_evals.py --base http://127.0.0.1:<端口>`。
3. 逐条核对完成标准。
4. 任一不过 → 打回，写清具体原因和期望。
5. 全过 → `git checkout master && git merge --no-ff task/...` → 冒烟复跑 → `git branch -d task/...`。

## 六、冲突预防清单（每次动手前自查）

- [ ] `TASKS.md` 的 `当前持棒` 是不是自己？不是就**只读不写**。
- [ ] 一次只推进一条任务，不并行开多条。
- [ ] 改动只落在任务白名单文件内。
- [ ] 每完成一个可验证单元就 commit，别攒大改动。
- [ ] 需要越界 / 改 API / 有新决策点 → 先在回执里提出，等我确认，别自己动。
