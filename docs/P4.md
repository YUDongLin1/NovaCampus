### 2.3 拒答门控失守（**P4 最高优先级**）

对照实验（student 角色，`POST /api/chat`，全部 `sources=[]`）：

| 问句 | 来源数 | 行为 | 判定 |
|------|--------|------|------|
| 反馈 F1 原文（长问句，含"某市""本学期已缴"情境） | 0 | 用自有知识给出 5 步流程 + 材料清单 + APP 名，并标注 **`[1]`** | **严重违规**（SYSTEM_PROMPT 规则 1/2/3/6 全破） |
| 「我参保地还在某市，怎么转到学校这边」（短问句） | 0 | 正确拒答，但末尾仍加 **`[1]`**，并夹带「根据国家医保局规定，跨省异地就医直接结算已逐步推广」 | **轻度违规**（虚构引用 + 无据断言） |
| 学平险 / 校车时刻 / 宿舍空调报修电话 / 成都天气 / 推荐股票 | 0 | 均正确拒答 | 合规 |

结论：
1. **失守与问句长度、情境丰富度正相关**——越像真实用户提问，越容易被模型当作"可回答的通用问题"。
2. **现有评测集测不出这个漏洞**：6 条 `refusal` 用例（`ref-01..06`）全是短问句/域外问题，所以拒答准确率长期 1.0，却仍发生真实事故。**评测覆盖盲区**，必须补「域内无据 + 长问句 + 含个人情境」用例类型。
3. 修复方向不是再加 prompt 规则（已有 9 条），而是**代码级硬门控**：`sources` 为空 → 不进 LLM 自由生成，走确定性拒答模板；答案里的 `[n]` 与 `sources` 做**硬校验**，越界编号直接剥离并记 badcase。

### 2.4 多轮上下文：不是"调整"，是"从零建"

代码事实（`novaagent/novaagent/agent.py`）：`chat_for()` 与 `chat_stream_for()` 构造的 `messages` **只有** `system`（含检索上下文）+ 当前 `user` 问题，**从不注入历史**。`db.add_message()` 只落库不回读；`GET /api/conversations` 返回的是一条**扁平消息流**（`messages` 表字段仅 `id/user_id/role/content/created_at`，**无 conversation_id**）。实测库里 user_id=3 累积 **754 条**消息混在一起，无法切分会话。

所以反馈 A3（多轮 + 上下文压缩 + 左侧会话列表）需要：新建 `conversations` 表 + `messages.conversation_id` 迁移 + 上下文注入 + 压缩策略 + 前端会话栏，是 P4 里工作量最大的一块。

### 2.5 联网搜索：来源可标注这条路已实测打通

- 现状 `llm.py` 走 **OpenAI 兼容模式**（`{LLM_BASE_URL}/chat/completions`）。实测该模式下即使 `enable_search=true` 触发了搜索（`usage.plugins.search.count=1`），**响应里没有 `search_info`** → 拿不到来源，无法满足"区分标注本地/联网来源"。
- 改用 **DashScope 原生协议** `POST /api/v1/services/aigc/text-generation/generation`，`parameters.search_options={forced_search, search_strategy:"turbo", enable_source:true, enable_citation:true, citation_format:"[<number>]"}` → 实测返回 `output.search_info.search_results[{index, site_name, title, url, icon}]`，答案正文自带 `[2]` 角标。**复用现有 `LLM_API_KEY`，零新增成本**（turbo 策略不额外计费）。
- 实测该通道还顺带定位到语料真实来源（`hospital.swjtu.edu.cn` 的《关于2026年度大学生医疗保险缴费的通知》等），见 §2.7。

### 2.8 rerank 层检索崩塌：F2 在语料补齐后**仍然答不上**（2026-09-29 实测，根因已定位并经变体矩阵修正）

> ⚠ **归因修正记录**：本节初稿把根因写成「**长问句**导致检索崩塌」——那是只看 2 个样本就下的结论。随后用 `evals/query_variant_matrix.py` 跑 8 种自然措辞（两遍数值一致）证伪了它：**崩塌与问句长度不单调**。7 字「学平险在哪里买」向量层排第 1、rerank 仍只有 0.1007 归零；48 字多子句书面句反而 0.4136 通过。以下为修正后的结论。

6 篇语料入库后（`documents 59→65`、`chunks 469→487`，`医保` 1→7、`学平险` 0→2、`参保` 0→7），复测三条反馈：

| 层 | 长问句「我们学校有学平险吗，我看我们计财处只有医保这项」 | 短问句「学平险」 | 「学生平安保险怎么理赔」 |
|----|------|------|------|

| `rag.search` 返回 | **0 条** | 2 条 | 4 条 |

**结论（修正版，均有变体矩阵数据支撑，见 `docs/p4/evidence/query_variant_matrix.txt`）**：
1. **不是语料问题**：文档已入库、向量层已把它排到第 2/3 位（部分措辞下排第 1）。
2. **是 rerank 层的崩塌 + 一刀切阈值**：同一份材料，「学平险」rerank **0.8875** 能命中，「学平险在哪里买」**0.1007** 归零，「学生平安保险是否由学校统一办理？」**0.0194** 归零——而这三句都是正常人会问的话。机制是 reranker 对"问句意图与分块字面内容不严格对应"就给极低分（材料讲理赔与投保，没讲"在哪里买"），`RERANK_MIN_SCORE=0.3` **既一刀切又无候选回退**，于是把"排序不佳"放大成"完全无来源"。
3. **崩塌与问句长度不单调**：7 字崩、16 字崩、48 字的多子句书面句反而通过（0.4136）。所以**不能用"句子长短"预测失败**，只能按措辞类型逐个测。
4. **真实措辞命中率仅 3/8 = 37.5%**：8 种自然问法里只有 3 种能把已入库的正确材料给到用户。
5. **关键词层同时是坏的**：`db.fts_search()` 用整句引号短语匹配，稍复杂的句子匹配不到就返回 None → 回退内存 2-gram 计次，而 2-gram 下"学校/我们/这项"等通用词把教育部令的 5 个分块顶上榜单。

**这与 §2.3 的拒答盲区同源**：评测集里的 13 条 qa 用例长度 8–17 字（均值 13.6）、句式与材料现成表述高度对齐，6 条 refusal 用例全是域外问题（天气/电影/火锅店/微信创始人）——**等于只考了"照着目录出的题"**。所以 R@k 0.9231、拒答 1.0 的漂亮指标下，真实问题仍会系统性失败。**P4 的评测建案规则**：新知识点必须"术语式短问 + 口语长问"**配对建案**，并保留真实用户原句作为用例。

**修复归属**：
- **P4a（M1）**：硬门控让 F2 这类失败**优雅降级**——不再胡答，而是走确定性拒答模板 + 正确出口（`contacts.json` 必须含**保卫处**（学平险归口）与校医院医保办），这是本轮能立刻拿到的改善；
- **P4d（M6）**：查询改写的**意图归一 + 术语展开**是根治手段（把「学平险在哪里买」归一为「学平险 办理/投保」类意图，而不是靠句子长短猜测），验收必须用 F2 原句断言命中；同时评估 `RERANK_MIN_SCORE` **分级阈值**与"目标文档标题命中核心术语时保底候选"——**一刀切 0.3 且无回退，会把"排序不佳"放大成"完全无来源"**；
- **P4d 同时评估**：`RERANK_MIN_SCORE=0.3` 是否改为「分级阈值」（如 top1 ≥0.3 或 top1/top2 差值判定），以及 `fts_search` 长句短语匹配失败时的回退策略（2-gram 计次应过滤停用词，避免通用词霸榜）。**注意 T10 的教训：不要单独调 `MAX_PER_DOC`。**

## 三、模块划分与实现方案

设计原则：**能用代码硬门控的，不再加 prompt 规则**（现状已有 9 条生成规则仍失守，见 §2.3）；**不引第三方重型框架**（LangGraph 只用作状态机编排，LLM/向量仍走现有 `llm.py` + numpy 路径）；**每个新能力都要有对应的评测用例类型**，否则等于没验收。

### M1 拒答硬门控与引用校验（→ P4a，最高优先级）

- **触发条件**：`rag.search()` 返回空，或 `top_score < RERANK_MIN_SCORE`（现有常量 0.3），或 `n_above_threshold < 2`。
- **行为**：不进 LLM 自由生成，返回**确定性拒答模板** = 「知识库暂无 X（说明缺口是什么）」+「建议出口」（部门/电话/官网，来自 M1 的出口数据表）+「如需精确答案请补充 Y」。允许 LLM 仅做措辞润色，但**不得新增任何事实**（实现上：模板由代码拼装，LLM 不参与）。
- **引用硬校验**：答案中所有 `[n]` 必须满足 `1 ≤ n ≤ len(sources)`，越界编号**由代码剥离**；一旦剥离即写一条 `fabricated_ref` badcase（复用 `evals/badcases.json` 机制）供追溯。
- **出口数据表**：新增 `novaagent/data/contacts.json`（或 DB 表 `contacts`）：`{dept, scope_keywords[], phone[], url, note}`。数据**必须来自官网原文**（§2.7 已实测到校医院 6 类电话），**不得由 LLM 生成**；按问题关键词匹配 1~3 条注入拒答模板。
- **评测**：新增用例类型 `refusal_indomain`（域内无据 + 长问句 + 含个人情境），断言 ①含"暂无" ②不含越界 `[n]` ③含出口电话或官网 ④不含流程性自有知识（用 `expect_absent_keywords` 反向断言，如"国家医保服务平台"）。**把 F1 原文直接作为一条用例**。
- **边界**：原文本身含 `[1]` 字样（引用条款编号）→ 校验只针对"编号 > 来源数"的情况，不误伤；`sources` 非空但分数极低 → 同样走拒答（避免"有来源但答非所问"）。

### M2 KB 卫生与导入质量门（→ P4a）

- **`smoke_test.py` 自清理**：记录本次上传的 `doc_id`，测试结束 `DELETE /api/kb/documents/{id}`；另加 `--cleanup` 模式清历史同名残留。**断言：冒烟跑完 `documents` 计数不变**（纳入 Review 闸门）。
- **导入质量门**（`main.py: kb_import_url` + `extract_html`，也作用于 `kb_upload`）：
  - 正文有效长度 < 200 字 → 拒；
  - 命中登录页/低信息量特征（`登录`、`用户名`、`密码`、`浏览器版本过旧`、`兼容性提示`、`请输入验证码`）→ 拒；
  - `<title>` 为 `登录`/`未命名网页` 等 → 拒；
  - 同 URL 已入库（`documents.filename` 唯一性）→ 拒并提示已存在；
  - 敏感扫描（复用 `corpus/anonymize.py` 的正则思路：手机号/身份证/学号/**人名+名单表格特征**）→ 命中即拒，提示人工审核。**含学生姓名的公示/名单页一律拦截**。
  - 拒绝时返回结构化原因（`{code, reason, hint}`），前端提示"疑似登录页/低信息量页面，请粘贴具体文章页 URL"。
- **KB 体检脚本** `evals/kb_doctor.py`：扫重复标题、超短正文、疑似登录页、口令/个人信息模式、category 与 audience 分布异常、孤儿分块、FTS 与 chunks 计数是否一致 → 输出 `reports/kb_doctor_<ts>.json`。本次清理的 17 篇就是它应该自动发现的类型。

### M3 语料扩充：医保 / 学平险 / 校医院 / 计财处（→ P4a，Qoder prep + 用户审）

- Qoder 产出 `docs/p4/corpus-candidates.md`（URL / 标题 / 发布日期 / 覆盖内容 / 建议 `category`+`role_min`+`audience` / 红线标注）→ **用户审批后**才入库。
- 入库走 M2 的质量门（等于给质量门做真实用例验证）。
- 目标覆盖：医保参保与转移接续（F1）、学平险的**有据否定**（F2：448 元构成中 48 元为自愿大病补充险，非商业学平险）、校医院科室与电话、缴费方式与时间。
- 每篇入库后抽查问答命中（对齐 T1 做法），并把 F1/F2/F3 三条真实问题转成 `qa` 用例，`expect_keywords` 取**官网原文关键词**（如「暂停原户籍地或学籍地参保关系」「448」「大病补充险」「028-66366439」）。

### M4 会话与上下文管理（→ P4b，工作量最大）

- **数据模型**：
  - 新表 `conversations(id, user_id, title, persona_id NULL, created_at, updated_at, archived INTEGER)`；
  - `messages` 加列 `conversation_id`（迁移：现有 836 条按 `user_id` + 时间间隔 >30min 切分为历史会话，**不删数据**；无法归属的进"历史归档"会话）；
  - 新表 `conversation_summary(conversation_id, summary_text, covered_until_message_id, updated_at)` 存压缩结果（原文永久保留在 `messages`，可回溯）。
- **上下文预算与压缩**（对应 A3 的"实时检测 + 65% 阈值"）：
  - token 估算零新依赖：`est_tokens ≈ ceil(chars / 1.6)`（中文经验值，文档标注为**估算**）；
  - `config.MODEL_CANDIDATES` 增 `ctx` 字段（各模型上下文窗口），`CONTEXT_BUDGET = ctx * 0.65`；
  - 未超预算 → 完整保留历史（时间正序）；超预算 → 对**较早**消息调 LLM 做「按主题分类压缩」（新增 `COMPRESS_PROMPT`，要求保留数字/日期/条款号/未决事项/对象代称），压缩摘要 + 最近 K 轮原文 + 当前问题一起注入；
  - SSE 增事件 `{"type":"context","used":n,"budget":m,"compressed":bool}`，前端显示占用条。
- **API**：`GET/POST /api/conversations`、`PATCH /api/conversations/{id}`（重命名/归档）、`DELETE /api/conversations/{id}`、`GET /api/conversations/{id}/messages`；`POST /api/chat` 与 `/api/chat/stream` 增 `conversation_id`（缺省自动新建）。
- **前端**：左侧会话栏（列表 + 新建 + 切换 + 重命名 + 删除），标题默认取首问前 20 字。
- **边界**：删除会话级联删消息与摘要；切换会话时中止进行中的 SSE（`AbortController`）；压缩调用失败 → 降级为"截断最早消息 + 前端标注已截断"；同一会话并发写（`_lock` 已有，按 conversation 粒度足够）。
- **评测**：新增类型 `multiturn`（第 2 轮用代词指代第 1 轮实体，断言答对）与 `context_compress`（构造超 65% 预算的历史，断言 `compressed=true` 且关键数字仍出现在答案里）。

### M5 KB 文件夹与 `@` 指定检索范围（→ P4c）

- **数据模型**：新表 `folders(id, name, parent_id NULL, owner_id, visibility, created_at)`；`documents` 加列 `folder_id`（NULL=根目录）与 `audience`（`undergrad`/`postgrad`/`common`，服务 F3 的学段区分）。`category` 保留为正交标签（两者不互斥）。
- **API**：`POST/GET/PATCH/DELETE /api/kb/folders`；`PATCH /api/kb/documents/{id}`（移动/归类/改 audience）；`POST /api/kb/documents/move`（批量）。
- **检索 scope**：`rag.search(query, min_rank, scope=None)` → `db.all_chunks_for_search(min_rank, folder_ids=None, audience=None)` 加 WHERE。**RBAC 优先于 scope**：取交集，越权的 folder **静默忽略**（沿用 `db.get_document()` 的「不可见 = 不存在」约定，不泄露存在性）。
- **`@` 语法**：前端输入框键入 `@` 弹出可选库（文件夹/分类）多选；**提交时 `question` 与 `scope` 分离传参**——`@xxx` 不得混进 question 文本，否则污染 embedding 与 FTS。
- **F3 学段处理**：`audience_hint` 缺失且问题命中「学段敏感清单」（荣誉称号/奖学金/学籍/请假/评优…）→ 走 M6 的 `clarify` 节点追问学段，或按学段分列两段答案（默认**追问**，因为猜错代价更高）。
- **前端**：KB 页由「表格 + 分类下拉」改为「文件夹树 + 文档列表」，支持新建/重命名/删除文件夹与文档移动。
- **边界**：删除非空文件夹 → **默认拒绝**并提示先移动（级联删除风险太高，若用户要级联需显式二次确认）；同层重名；跨 `role_min` 移动（文件夹 visibility 不得放宽文档权限）；`@` 指定的库为空 → 明确提示，**不得静默回落全库检索**。
- **评测**：新增类型 `scoped_qa`（`@` 指定库后断言来源全属该库；`@` 空库断言返回提示而非全库结果）。

### M6 LangGraph 检索编排与查询改写（→ P4d）

- **依赖**：`novaagent/pyproject.toml` 增 `langgraph`（传递引入 `langchain-core`）。PyPI 清华源与官方源实测均 200 可装。**只用 LangGraph 做状态机编排**，LLM 调用仍走 `llm.py`（httpx）、向量仍走 numpy 内存余弦——不引入 langchain 的模型/向量/retriever 封装，避免与自研栈重复。
- **图结构**：
  ```
  intent ─┬─(chitchat/time/meta)→ direct_answer        # 跳过检索
          └─(need_retrieval)→ retrieve → grade ─┬─达标→ generate
                                                └─不达标→ rewrite → retrieve (≤MAX_REWRITE=2)
                                                          └─仍不达标→ refuse_with_exit  # 复用 M1 硬门控
  ```
- **意图判定**：轻量 LLM 调用（qwen-flash、temperature 0、JSON 输出 `{intent, need_retrieval, audience_hint, time_expr}`）；**问时间/日期类不调 LLM**（正则 + `datetime` 直接答，省一次往返）。
- **召回质量信号**（`grade` 需要，现在 `rag.search` 不返回）：改造返回 `{sources, top_score, n_above_threshold, fused_candidates, rewritten_from}`。判定：`top_score ≥ 0.3` 且 `n_above_threshold ≥ 2`（可配）。
- **改写策略**：① **意图归一 + 术语展开**（学平险 ↔ 学生平安保险 ↔ 意外伤害保险理赔；实测这是 F2 崩塌的主因，**不是句子长短**）② 去情境噪声（对应 F1 的拒答失守场景）③ 学段限定 ④ 拆子问题。每次改写写入 `retrieval_trace`，前端可展示「检索尝试 1/2/3」。
- **状态持久化**：graph state 落 `conversations.retrieval_trace`（JSON 列，M4 建表时一并加），便于复盘与评测断言。
- **边界**：意图判定超时/失败 → **降级为默认走检索**（保守，路由挂了不能不答）；改写循环上限；流式路径与图编排兼容（SSE 增 `{"type":"trace"}` 事件）。
- **评测**：新增类型 `intent`（闲聊/问时间断言 `retrieval_trace.skipped=true`）与 `rewrite`（口语化长问句断言发生改写且最终命中）。**性能必须给实测毫秒数**：闲聊路径首字延迟应显著低于检索路径，普通问答不得劣化。

### M7 联网搜索开关与来源分区（→ P4e）

- **新增 `novaagent/websearch.py`**：DashScope 原生协议客户端（`POST /api/v1/services/aigc/text-generation/generation`），`parameters.search_options={forced_search:true, search_strategy:"turbo", enable_source:true, enable_citation:true, citation_format:"[<number>]"}`，解析 `output.search_info.search_results[{index,site_name,title,url}]`。**实测可用**（§2.5），复用现有 `LLM_API_KEY`。
- **编排**：开关开 → 在 M6 图里 `retrieve` 之后并行 `web_search` 节点 → 联网结果映射为 `[W1..Wk]`，与本地 `[1..n]` **分区注入**（system prompt 两个区块：本地知识库资料 / 联网检索资料），生成规则要求「本地用 `[n]`、联网用 `[Wn]`，不得混用，联网内容须注明站点名」。
- **开关粒度**：用户级默认（`user_settings.web_search_enabled`）+ 单次请求覆盖（`POST /api/chat {web_search:true}`）；前端输入框旁显式开关，**默认关闭**（用户自主决定）。
- **前端**：来源区分「知识库来源」与「联网来源」两块；联网来源显示 `site_name + title + 可点 url`，并标注「联网结果未经本校核实」。
- **合规红线**：联网请求**只发送当前问题文本**——绝不发送库内文档内容、会话历史、学生个人信息；含学生姓名的公示/名单页不得作为语料回填。
- **边界**：搜索超时/失败 → 降级为仅本地 + 明确提示「联网搜索不可用」；无结果 → 提示；引用编号越界校验同 M1；计费与配额记录 `usage.plugins.search.count`。
- **评测**：新增类型 `web_grounded`（开关开问库内无据但公网有答的问题，断言含 `[W1]` 且来源可点；**开关关时同一问题必须走 M1 拒答模板**）。

### M8 辅导员定制 + 侧边栏重构（→ P4f）

- **数据模型**：新表 `personas(id, owner_id, name, college, persona_prompt, style, bound_folder_ids JSON, bound_categories JSON, visibility, is_default, created_at)`；`conversations.persona_id` 关联。
- **权限**：辅导员可建/改自己的 persona；学生只能用 `visibility=public` 的；admin 管全部。**绑定的库仍受 RBAC 交集约束——persona 不得提权**。
- **prompt 组装**：`SYSTEM_PROMPT` 从模块级常量改为 `build_system_prompt(persona, ctx_local, ctx_web)`；**防幻觉规则 1–9 硬编码在模板里，persona 的人设/风格段不得覆盖或删改**（防 prompt 注入绕过约束）。
- **前端**（对应 A5）：统一左侧会话栏（会话列表 + 新建 + 当前辅导员选择器），**账户入口移到会话栏最底部**；新增「辅导员」入口 → 创建/编辑表单（名称、学院、人设提示词、回复风格、绑定知识库多选）；对话中可直接切换辅导员作答。
- **边界**：persona 删除后其历史会话保留并标记「人设已删除」；绑定库为空 → 提示；自定义人设里的越权指令（「忽略以上规则」）→ 规则段不可覆盖 + 输出侧引用校验兜底。
- **评测**：新增类型 `persona`（同一问题在两个 persona 下断言风格差异且来源一致；用注入攻击问句断言规则未被绕过）。

### M9 UI 细节（→ P4g）

- `#w-content`（周报谈心谈话文本框，对应 F4）：提升 `rows`/`min-height`、随输入自动增高（`scrollHeight`）、保留可拖拽 resize。
- 会话栏 / 来源分区 / 联网开关 / 辅导员选择器的样式沿用 T3 建立的「学术水墨 × 朱砂印」主题，**不引第三方 UI 库**。
- 验收：改动前后截图对比 + 三角色手工走查。

## 四、排期与依赖（串行持棒，全部在 P3b 合并之后）

```
P3b(AIOps MCP,已下发) → P4a(M1+M2+M3) → P4b-0(前端拆分) → P4b(M4) → P4c(M5) → P4d(M6) → P4e(M7) → P4f(M8) → P4g(M9)
```

排序理由：
1. **P4a 最先**——M1 是安全底线（无据也答 + 虚构引用是真实事故），M2 堵住持续污染，M3 直接回应三条用户反馈。三者都不依赖新表结构，可独立验收。
2. **P4b（会话）先于 P4d/P4f**——M6 的 `retrieval_trace` 与 M8 的 `persona_id` 都挂在 `conversations` 上。
3. **P4c（文件夹/audience）先于 P4f**——persona 要绑定文件夹。
4. **P4d（编排）先于 P4e**——联网搜索是图里的一个节点。
5. **P4g 收尾**——纯 UI 细节，等结构稳定后一次做完，避免反复改 `index.html`。

> ✅ **前端拆分已定（用户 2026-09-29）**：`web/index.html` 887 行单文件在 **P4b 开工前**先拆，独立成单 **P4b-0**（纯重构、零构建、行为不变、三角色走查 + 评测零回归为验收）。因 P4a 与 P4b-0 都会触碰 `main.py`（前者导入质量门、后者静态路由），**两单必须串行，严禁并行开**。
