════════════════ 第一部分:P4f 第一版(修 C0-⑤ 的两个真缺陷)════════════════

【第 1 次 :8941,修复前】
  [probe] llm_key_source = 'repo_dotenv'
  [RESULT] 5/5 passed
  [port-check] :8941 closed=True
  EXIT=4   <-- ❌ 假红:退出码与事实相反(端口确实关了却退 4)

  暴露的两个真缺陷:
    ① taskkill //PID $SRV 用的是 MSYS PID,Windows 侧找不到该进程 → 静默失败,
       脚本一路退化到 shell kill(坑 61:kill 返回成功不等于进程真死)。
    ② 更严重:主流程 `if ! port_closed; then exit 4; fi` 写在终止动作**之前** ——
       那一刻进程还活着、端口必然在听 → **恒 exit 4**;紧接着 EXIT trap 才真正
       杀掉进程并打印 closed=True。退出码与事实相反,比不报错更坏。

【第 2 次 :8942,修复后】
  [server] taskkill //PID 38724 //F (端口 8942 上的 Windows PID)
  [port-check] :8942 closed=True
  EXIT=0

  修复内容:
    ① terminate_server 改为**按端口反查 Windows PID** 再 taskkill,拿不到才退 SRV,
       再退 shell kill —— 三段降级,权威依据是端口而非 PID 变量。
    ② 收尾与端口复查移到主流程显式执行(cleanup 幂等,CLEANED 标志防重复打印),
       判定发生在终止**之后**。
