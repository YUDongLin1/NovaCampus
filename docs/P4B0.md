> ⚠ **字节数口径（复核时补）**：上表字节数是 **LF 形式**（= git blob 里的字节数）。本机 `core.autocrlf=true`，
> 所以每次 `checkout`/`merge` 之后**工作区**文件会变成 CRLF、每行多 1 字节（如 `theme.css` 22,102 → 22,455）。
> 后续做字节对账必须先归一行尾，否则会出**假 DIFF**——本次复核就是这么撞出来再追清的（见 HANDOFF 坑 36）。

`main.py` 新增 25 行、**删除 0 行**：`/css/{name}`、`/js/{name}` 两条只读静态路由。
**为什么不用 `StaticFiles`**：Windows 下 `mimetypes` 受注册表影响，`.js` 可能被猜成 `text/plain`，浏览器严格 MIME 校验会**直接拒绝执行脚本 → 页面白屏**。故显式给 `media_type`，并做目录穿越与后缀校验（实测 `/js/..%2Fcss%2Ftheme.css`、`/js/main.py` 均 404）。

## 五、顺手发现的两条既存缺陷（**未修**，转后续单）

1. **质量门的 `hint` 从没到达用户**（转 **P4g**，小改）：P4a 把导入拒绝改成返回 `{code, reason, hint}`（dict），但前端 `api()` 只会渲染**字符串** `detail`，遇到 dict 就回退成 `HTTP 400`。实测：counselor 导入导航页 → 界面只显示 **"导入失败：HTTP 400"**，用户看不到"请粘贴具体文章页 URL"这句关键提示。
   修法（P4g）：`api()` 里 `detail` 为对象时拼 `reason + hint`。属前端行为变更，故不能塞进本单。
2. **`importUrl()` 依赖全局 `event`**（`const btn = event.target`）：只能从内联 `onclick` 调用，脚本直呼会 `TypeError`。既存写法，拆分前后一致；若后续要单测/自动化驱动，需改为显式传参。
