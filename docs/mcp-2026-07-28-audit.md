# MCP 协议 2026-07-28 修订审计说明

审计对象：周报 MCP 服务（`mcp/weekly`）、AIOps MCP 服务（`mcp/aiops`）、主服务周报客户端
（`novaagent/novaagent/weekly_client.py`）。对照点为 2026-07-28 修订版协议与 Python SDK
`mcp==2.2.0` 的实际实现（SDK 内 `LATEST_MODERN_VERSION = "2026-07-28"`）。

## 一、2026-07-28 修订要点（本次审计的对照基线）

- **无握手**：`initialize` / `notifications/initialized` 取消；每个请求自带协议版本与客户端
  能力（`params._meta` 的 `io.modelcontextprotocol/*` 键），版本不匹配返回结构化错误。
- **无会话**：`Mcp-Session-Id` 取消；需要跨调用状态的服务端自己发显式 handle、当普通工具
  参数传，不再依赖协议层会话。
- **无服务端主动请求**：elicitation / sampling 由 MRTR（`input_required` + 客户端重试）取代；
  Roots、Sampling、Logging 进入弃用流程（官方弃用页：最早移除时间为 2027-07-28 后的修订版）。
- **传输**：HTTP+SSE 早在 2025-03-26 就已弃用，2026-07-28 修订将其正式归入 Deprecated；
  唯一推荐传输是 Streamable HTTP 单端点；现代请求还要求 `Mcp-Method` 头与 body 的 method 一致。
- **发现**：服务端必须实现 `server/discover`，客户端可据此做版本协商；旧版客户端仍可用
  `initialize` 握手与旧版服务端互通（SDK 内称 handshake-era 版本）。

## 二、审计结论（逐项）

| 对照项 | 周报服务 | AIOps 服务 | 主服务客户端 |
| --- | --- | --- | --- |
| 传输 | 挂 `/sse`（已弃用）+ `/mcp`（有状态模式）→ **改** | 同左 → **改** | 已走 `/mcp`，不用改 |
| 握手/会话 | `/mcp` 接受旧版有状态会话 → **改无状态** | 同左 → **改无状态** | 显式 `initialize()`（已取消）→ **改时代协商** |
| SDK 版本 | `mcp==2.2.0`，已支持 2026-07-28，**不用升级** | 同左，**不用升级** | 同左，**不用升级** |
| server/discover | SDK 低层服务已内置，**不用改** | 同左，**不用改** | 协商时自动探 discover |
| Roots / Sampling / Logging / 订阅 / 任务 | 均未使用（工具全是请求-响应式）→ **无改动** | 同左 → **无改动** | 未使用相关回调 → **无改动** |

一句话结论：**SDK 不用升，旧传输与旧握手必须改**。两个服务的 `/mcp` 在升级前其实已能
服务现代客户端（SDK 按协议版本头把现代请求路由到无状态单交换处理器），但同时还挂着已弃用
的 SSE、还接受旧版有状态会话；主服务客户端则一直走已取消的 `initialize()`。本次升级把这
三处一次性收敛到现代形态。

## 三、改了什么

- `mcp/weekly/server.py`、`mcp/aiops/server.py`：删 `sse_app` 挂载（`/sse`、`/messages/` 下线），
  `streamable_http_app` 改传 `stateless_http=True`；lifespan 只保留 `/mcp` 一路。
- `novaagent/novaagent/weekly_client.py`：`initialize()` 改为 SDK 的时代协商 `negotiate_auto`
 （先探 `server/discover`，现代服务器走无状态流程，遇旧服务器自动回落 `initialize`）。
- `mcp/weekly/tests/smoke_test.py`、`mcp/aiops/tests/smoke_test.py`：删 SSE 一腿，`/mcp` 一腿
  改用时代协商。
- 文档同步：`mcp/weekly/README.md`（WeKnora 注册改走 `/mcp`）、`mcp/aiops/README.md`、
  根 `README.md`、运维手册、`docs/P3B.md` 中所有“双传输 / SSE”字样；`CHANGELOG.md` 记一笔。
- **没动**：检索链路、RBAC 权限逻辑、两个服务的工具集与业务代码；周报降级与懒重连语义保留，
  并补了两处加固（见第五节）。

## 四、兼容性实测（升级后，干净检出 + 新鲜数据目录）

- 现代客户端（时代协商 → discover 模式）：周报 14 工具、AIOps 7 工具可见可调；原始
  `tools/list`（带 `Mcp-Protocol-Version: 2026-07-28` + `Mcp-Method` 头 + `params._meta`）返回
  200，`resultType: complete`；现代版 `initialize` 返回 404 Method not found（符合“握手已取消”）。
- 旧版 SDK 客户端（`initialize()` + 工具调用）：升级后仍能走通（SDK 的无状态旧版路径按单请求
  处理，不建会话）。即：旧客户端不断连，但依赖会话/订阅/通知的用法不再支持——本仓库两个
  服务本来就没有这类用法。
- `/sse`：GET 返回 404，已下线。
- 周报冒烟（`mcp/weekly/tests/smoke_test.py`）：`SMOKE TEST PASSED`（碎片记录、分类回落、
  周报渲染、归档、列表/读取、清理全流程）。
- 7 个离线 CI 套件（`test_p4b_fix_gate`、`test_p4f_frontend_contract`、`test_p4f_persona`、
  `test_p4f_persona_eval`、`test_p4f_persona_eval_wiring`、`test_prompts_hygiene`、
  `test_records_board`）：本地全绿。

## 五、降级与懒重连链路（升级后实测）

- 周报服务未启动：`start()` 返回 False（不抛错），`call()` 返回 `weekly MCP 未连接`，
  主服务启动不受影响。
- 服务中途停掉：当次调用返回错误字典（不抛错、不阻断对话），且本次失败后 session 被 reset，
  下一次调用重新协商——**这是本次顺带修掉的旧问题**：旧代码在调用抛错后仍留着已断的 session，
  服务恢复后后续调用会一直失败（实测 `Connection closed`），直到主服务重启。
- 服务恢复后：下一次调用懒重连成功（实测：停 → 错 → 起 → 通，全程不重启主服务）。
- 另一处顺带加固：SDK 传输失败时可能以 `CancelledError` 形式抛到调用方（传输内部任务组
  取消了等待响应的协程），旧代码的 `except Exception` 拦不住它，会导致 `start()` 抛错；
  现 `start()` / `stop()` / `call()` 统一把 `CancelledError` 按连接失败处理（裸事件循环复现：
  旧代码与新代码此前都会从 `start()` 逃出 `CancelledError`，现已消除）。

## 六、未验证项与部署注意

- AIOps 冒烟（`mcp/aiops/tests/smoke_test.py`）需要 sims 监控栈（Prometheus :9090 + 宿主机
  docker CLI），本机未跑；本次只验证了协议层（discover 模式 + 7 工具可见）。无 Prometheus
  环境下 `get_service_status` 返回 `_err`（工具自身的环境依赖，非协议问题）。
- **WeKnora 注意**：若 WeKnora 仍用旧 SSE 地址（`http://weekly-mcp:8000/sse`）注册，升级后
  需改到 `http://weekly-mcp:8000/mcp`（`docker-compose.weekly.yml` 本来就写的是 `/mcp`；
  只有 `mcp/weekly/README.md` 里那段 v0.8.2 时期的 SSE 注册说明是旧的，现已同步改掉）。
- `negotiate_auto` 来自 `mcp.client._probe`，`mcp 2.2.0` 未从 `mcp.client` 公开导出它；
  将来升级 SDK 大版本时需复核该导入路径（代码里已留注释）。
