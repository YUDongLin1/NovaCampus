# 校园模拟系统运维手册——一卡通与教务(P3 占位框架)

> 本文为 P3 AIOps 智能诊断的对齐占位:模拟校园系统(一卡通/教务)建成后将扩充为完整运维手册。当前先固化诊断叙事所需的"故障预案骨架",保证 Agent 诊断报告有据可引。

## 一、系统清单(拟)

| 模拟系统 | 端口 | 核心依赖 | 关键指标(Prometheus) |
|----------|------|----------|----------------------|
| 一卡通模拟 | 9001 | 连接池(数据库) | http_5xx_rate / db_pool_in_use / response_p95 |
| 教务模拟 | 9002 | 内存缓存 | cpu_usage / mem_usage / gc_pause_ms |

## 二、告警分级(拟)

- **P1(页面级故障)**:5xx 率 >5% 持续 2 分钟,或服务不可达 → 立即响应;
- **P2(降级)**:p95 >2s 持续 5 分钟,或连接池占用 >80% → 30 分钟内响应;
- **P3(隐患)**:错误日志出现堆栈、磁盘/内存水位告警 → 当日处理。

## 三、典型故障预案骨架(与 P3 故障注入对齐)

### 3.1 一卡通连接池耗尽

- **现象**:消费/查询接口大量超时,日志出现 `connection timeout`,`db_pool_in_use` 顶格。
- **取证**:连接池指标曲线、慢查询日志、最近变更(发版/批量任务)。
- **根因假设**:慢查询占住连接未释放 / 连接池上限配置过低 / 批量任务挤占。
- **处置**:重启服务恢复 → 定位慢查询并加索引/限流 → 调整池上限 → 复盘变更。
- **预案依据**:本手册 3.1 节(Agent 诊断报告应引用此条)。

### 3.2 教务系统 CPU 飙高

- **现象**:选课/成绩查询高峰 CPU 持续 >90%,接口变慢。
- **取证**:CPU 曲线与业务高峰对齐、线程 dump、慢 SQL。
- **根因假设**:全表扫描查询 / 缓存失效穿透 / 死循环任务。
- **处置**:限流降级 → 定位热点查询 → 加缓存/索引 → 压测验证。
